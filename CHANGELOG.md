# v3.0.0 (The Lighthouse 🗼)

> A new organization, made to be customized without ever conflicting with updates. **Breaking changes**, but the migration is automatic: read the [V3 Migration Guide](doc/UPGRADE_V3.md).

## What's new?

### New organization 🗂️

* [**config**] New ``config.yaml`` format: default values of each service (Traefik rules, dependencies) are now in the service itself (``services/<name>/service.yaml``). You only write what you want to change, and a new ``defaults`` section applies a parameter to all rules. See the [Configuration Guide](doc/configuration.md#configuration-structure-and-parameters).
* [**script**] You never have to edit a file tracked by git anymore, so updates never conflict with your changes. See [Your files and the files of the project](doc/configuration.md#your-files-and-the-files-of-the-project).
  * Customize a bundled service with an override file (``services/<name>/custom/compose.override.yaml``), merged on top of the bundled one. See [Customize a bundled service](doc/configuration.md#customize-a-bundled-service).
  * Traefik configuration files are now yours (``services/traefik/custom/traefik.yaml``, ``middlewares.yaml``, ``tls.yaml``), created from templates (``*.sample.*``) like ``.env`` or ``config.yaml``.
  * The directory mounted in the Traefik container is now generated on each run (``services/traefik/generated-config/``): the script does not modify your ``traefik.yaml`` anymore when ``TRAEFIK_CUSTOM_ACME_RESOLVER`` is set.
* [**script**] One directory per service: ``services/<name>/compose.yaml``, with its default values (``service.yaml``), an optional ``rules.yaml`` (Traefik config file applied when the service is enabled) and its other configuration files.
* [**script**] All your own additions are now in the ``custom`` directory of each service (``services/<name>/custom/``, ignored by git): your changes on a bundled service, your own services (no more ``customFile`` needed) and, for Traefik, your own rules (``services/traefik/custom/rules/``).
* [**config**] ``.env.custom`` is replaced by one environment file per service (``services/<name>/custom/service.env``), without prefix on variables. Services which need or support variables provide a ``service.sample.env``: your file is created from it when you enable the service, required variables (``changeme``) are checked and optional ones are commented. See [Environment variables](doc/configuration.md#environment-variables).
* [**script**] New ``tools/sync-templates.sh`` script, called by ``run-seedbox.sh`` and ``init.sh``: it creates your files from the templates and, when a template changes after an update, merges the change in your file (or warns you if it cannot). Use ``status`` and ``diff`` to see where you stand. See [Templates](doc/configuration.md#templates).
* [**script**] Files generated by the script are now in ``.seedbox/`` (ignored by git) instead of ``services/generated/`` and ``env/``.
* [**script**] The ``local-persist`` Docker plugin is not needed anymore: services mount the directories of ``HOST_CONFIG_PATH`` directly, at the same place as before. Nothing to install as ``root``, and nothing to migrate. Media (``torrents``, ``downloads``, ``documents``) stay shared volumes defined in ``docker-compose.yaml``, plain directories or NFS share.

### New features ✨

* [**Traefik**] New ``internalOnly`` parameter on rules: the service is only reachable from your private networks (``internal-only`` middleware, to adapt in your ``middlewares.yaml``).
* [**Traefik**] Client certificates (mTLS): new ``mtls`` parameter on rules, to restrict a service to the devices which own a certificate you created. The script stops if a rule requires a certificate and no Certificate Authority is found. See [VaulTLS and client certificates](doc/apps/vaultls.md).
* [**Traefik**] Static IP for a service: ``docker-compose.sample.yaml`` has a (commented) ``ipam`` block which keeps a part of the network for static IPs, so no other container can take them. See [Static IP for a service](doc/configuration.md#static-ip-for-a-service).
* [**Traefik**] Traefik is restarted by ``run-seedbox.sh`` when its static configuration (``traefik.yaml``) has changed.
* [**script**] Dependencies between services are declared by services (``requires`` in ``service.yaml``) instead of being hard-coded in the script.
* [**config**] ``config.yaml`` is now checked: the script stops on any unknown parameter, so a typo (``interalOnly``...) cannot silently leave a service unprotected. Parameters are described in a new ``config.schema.json``, which also gives completion and validation in editors supporting YAML schemas. It is generated by the new ``tools/generate_schema.py``.
* [**script**] ``run-seedbox.sh`` can be called from any directory (cron, absolute path...).
* [**script**] The script does not read ``.env`` on its own anymore: it asks Docker Compose for the values, so both always see the same ones (quotes, special characters...).
* [**script**] The name of the Docker Compose project is now always ``seedbox`` instead of the name of the directory: the directory of the seedbox can be renamed or moved.
* [**script**] Missing directories of services (in ``HOST_CONFIG_PATH``) and of media volumes are created by the script, owned by the user of the containers (``PUID`` and ``PGID``) instead of ``root``.
* [**Nextcloud**] ``tools/init-setup-nextcloud.sh`` reads its variables from the environment files of ``mariadb`` and ``nextcloud``.
* [**script**] The installed version is saved in ``.seedbox/version``, to make future migrations reliable.
* [**script**] Clear error when the docker-compose file of a service does not exist.

## Bugfixes and improvements ⚙️

* [**Jackett**] Fix: Jackett had access to the whole config directory and changed the owner of the files of all other services each time it started. It now only uses its own directory (same place as before, nothing to migrate).
* [**ntfy**] Authentication is now enabled (login required, no anonymous access). Create your users with ``NTFY_AUTH_USERS`` in ``services/ntfy/custom/service.env``. New persistent directory: ``$HOST_CONFIG_PATH/ntfy-auth``.
* [**Netdata**] Now runs in host network mode with more access to the host (processes, logs, disks) for complete metrics. As a consequence it is not exposed through Traefik anymore: use ``http://<your-server>:19999``. Image tag is now *latest* instead of *stable*.
* [**Calibre**] ``CALIBRE_PASSWORD`` variable is removed: it was not applied since v2.2 (and showed a warning on each run). Nothing changes: Calibre is still protected by the http authentication of its Traefik rule (``httpAuth: true`` by default).
* [**FlareSolverr**] Use ``nodriver`` driver.
* [**Traefik**] The Docker socket is now mounted read-only in the Traefik container.
* [**Traefik**] Security headers: deprecated options are replaced in the ``middlewares.yaml`` template (``featurePolicy`` becomes ``permissionsPolicy``, ``browserXssFilter`` is removed).
* [**Nextcloud**] The container has no access to the whole config directory of the seedbox anymore (``/seedbox-config``).
* [**Tautulli**] The container only sees the config directory of Plex (read-only, in ``/plex``) instead of the whole config directory of the seedbox.
* All services now use the ``unless-stopped`` restart policy: a container you stopped yourself is not started again when Docker restarts.
* [**init**] ``init.sh`` does not create the Docker network anymore: it is created by Docker Compose.
* Removed obsolete tools and guides: ``tools/legacy/``, ``tools/wip/``, ``tools/config-updater/`` (v1 to v2 migration) and the Traefik v1 to v2 guide.
* [**Nextcloud**] MariaDB is now enabled in the sample configuration, as Nextcloud requires it.
* [**init**] Fix #68: ``local-persist`` driver is not installed anymore (see above).
* [**script**] ``CHECK_FOR_OUTDATED_CONFIG`` variable is removed: you are now warned each time a sample file changes, and ``tools/sync-templates.sh diff`` shows you what changed.
* [**doc**] New [V3 Migration Guide](doc/UPGRADE_V3.md), [Netbird](doc/apps/netbird.md), [VaulTLS](doc/apps/vaultls.md), [Dockhand](doc/apps/dockhand.md), [FileBrowser Quantum](doc/apps/filebrowser.md) and [Plex](doc/apps/plex.md) guides. [Configuration Guide](doc/configuration.md) rewritten for the new organization.
* Fix typos in ``.env.sample`` and broken links in ``README.md``.

## Upgrade notes ⚠️

* ``./run-seedbox.sh`` migrates your installation automatically (``config.yaml``, ``.env.custom``, your own services and Traefik files). Your previous ``config.yaml``, ``.env.custom`` and ``traefik/`` directory are saved in ``.seedbox/backup/``.
* If you edited files tracked by git in ``services/`` or ``traefik/``, ``git pull`` will refuse to update them: see [this section](doc/UPGRADE_V3.md#if-git-pull-fails). Your changes in ``traefik/traefik.yaml`` and ``traefik/custom/*.yaml`` are not carried over: report them in ``services/traefik/custom/``.
* [**Removed services**] ``Overseerr``, ``Readarr``, ``Ombi``, ``Homarr`` and ``Portainer`` are not bundled anymore: these projects are discontinued, or replaced here by another service. If one of them is enabled in your ``config.yaml``, the script stops because its file does not exist anymore.
  * Replacements: Seerr for Overseerr and Ombi (rename ``overseerr`` to ``seerr``, and see the [Seerr migration guide](https://docs.seerr.dev/migration-guide) to keep your data), Dockhand for Portainer, Homepage or Heimdall for Homarr.
  * Still need one of them? Keep it as your own service, in one command: see [Removed services](doc/UPGRADE_V3.md#after-the-migration) and [Add your own service](doc/configuration.md#add-your-own-service).
* [**Filebrowser**] The original Filebrowser is discontinued (archived repository): the ``filebrowser`` service now runs FileBrowser Quantum. It is another application, so users, settings and shares are not migrated (your files are not affected). A password is now required for its ``admin`` user (``services/filebrowser/custom/service.env``, the script asks for it), its data is in ``$HOST_CONFIG_PATH/filebrowser-quantum`` and its default rule has no http authentication anymore, as the application has its own. See [its documentation](doc/apps/filebrowser.md#coming-from-the-previous-filebrowser).
* [**Docker Compose**] Docker Compose v2 (``docker compose`` command, 2.27.2 or above) is now required. The ``DOCKER_COMPOSE_BINARY`` variable is removed and the old ``docker-compose`` binary is not supported anymore.
* [**Docker Compose**] If the directory of your seedbox is not named ``seedbox``, the new project name requires to remove and create all containers again (not their data): the script asks you before doing it. Set ``COMPOSE_PROJECT_NAME`` in your ``.env`` to keep the previous name instead. See the [V3 Migration Guide](doc/UPGRADE_V3.md#after-the-migration).
* [**local-persist**] Your ``docker-compose.yaml`` and your own services may still use volumes of the plugin: they keep working as long as it is installed, and the script lists them. See [how to get rid of it](doc/UPGRADE_V3.md#local-persist-plugin).
* [**script**] Unused Docker images and volumes are not removed anymore after each run, as it applied to the whole host and not only to the seedbox. Set ``DOCKER_PRUNE_AFTER_UPDATE=true`` in your ``.env`` to get the previous behaviour back.
* [**Traefik**] Administration tools are private by default: the default rules of the Traefik dashboard and Dockhand now have ``internalOnly: true`` (like VaulTLS), so they are only reachable from your private networks. Write ``internalOnly: false`` on their rule in ``config.yaml`` to publish them. Installations migrated from v2 are not changed: the migration keeps your Traefik dashboard reachable as before, with an explicit ``internalOnly: false`` that you may want to remove.
* [**Plex**] Its default Traefik rule is removed: Plex uses the network of the host, so Traefik cannot reach it by its name. Use the port ``32400``, or publish it on ``plex.yourdomain.com`` with Netbird: see [Plex documentation](doc/apps/plex.md). Rules you may have for ``plex`` in your ``config.yaml`` are kept by the migration.
* [**Traefik**] HTTP to HTTPS redirection is now global (set on the entrypoint in ``traefik.yaml``) instead of being a middleware on each rule, and generated rules only use the HTTPS entrypoint. ``httpOnly`` rules still work: see [Disable HTTPS completely](doc/configuration.md#disable-https-completely) for the details. The ``redirect-to-https`` middleware, not needed anymore, is removed from ``middlewares.yaml``: if your own Traefik rules use it, remove it from them or add it back in your file.
* [**Netdata**] Its default Traefik rule is removed (see above). If your ``config.yaml`` has rules for ``netdata``, remove them: they cannot reach it anymore.
* [**config**] ``customFile`` is now relative to the directory of the service. Plex hardware transcoding file is now ``compose-hardware-transcoding.yaml`` (updated by the migration).
* [**NFS**] The sample file moved from ``samples/docker-compose.sample.nfs.yaml`` to ``docker-compose.nfs.sample.yaml``. ``samples/`` directory does not exist anymore.
* [**ntfy**] As authentication is now enabled, your clients and scripts must use a user or a token. The http authentication of Traefik is therefore disabled in its default rule (``httpAuth: false``), as both cannot be used together. The migration keeps ``httpAuth: true`` if you had it: remove it from your ``config.yaml``.
* [**Nextcloud** / **Tautulli**] If you used the config directory of the seedbox from these containers (``/seedbox-config`` in Nextcloud, ``/logs`` in Tautulli), add the volume back with an override file (see [Customize a bundled service](doc/configuration.md#customize-a-bundled-service)). In Tautulli, the logs of Plex are now in ``/plex/Library/Application Support/Plex Media Server/Logs``.

## ⚠️ Config changes ⚠️

### Nextcloud and DB

MariaDB is now a separate service, and nextcloud is still dependant on it.
In order to enable ``mariadb`` service, either refer to ``config.sample.yaml`` or add the following to your ``config.yaml`` file:

```yaml
# [...]
  - name: mariadb
    enabled: true
    vpn: false
    traefik:
      enabled: false
      rules: []
# [...]
```

### Variables

Due to the refactoring of the app-specific variables (by using ``.env.custom`` file), some old variables present  in ``.env`` must be moved to ``.env.custom`` and prefixed with the service name.

> The ``run-seedbox.sh`` script will detect obsolete configuration in .env and will notify yo and stop to prevent config errors.

If the following variables are present (not commented not absent) in your ``.env`` file, copy it in the new ``.env.custom`` file (either copy the value by using the placeholder already in place in the new file or overriding completely the file).

| Variable in **.env**  | Variable in **.env.custom** |
|---|---|
| Variables starting by ``MYSQL_`` | Add prefix ``MARIADB_`` |
| Variables starting by ``NEXTCLOUD_``| Add **another** ``NEXTCLOUD_`` prefix |
| Variables starting by ``PAPERLESS_`` | Add **another** ``PAPERLESS_`` prefix |
| Variables starting by ``PORTAINER_``| Add **another** ``PORTAINER_`` prefix |
| Variable named ``FLOOD_PASSWORD`` | ``FLOOD_FLOOD_PASSWORD`` |
| Variable named ``CALIBRE_PASSWORD`` | ``CALIBRE_CALIBRE_PASSWORD`` |
| Variable named ``WIREGUARD_ENDPOINT`` | ``GLUETUN_VPN_ENDPOINT_IP`` |
| Variable named ``WIREGUARD_PORT`` | ``GLUETUN_VPN_ENDPOINT_PORT`` |
| Variable named ``WIREGUARD_PUBLIC_KEY`` | ``GLUETUN_WIREGUARD_PUBLIC_KEY`` |
| Variable named ``WIREGUARD_PRIVATE_KEY`` | ``GLUETUN_WIREGUARD_PRIVATE_KEY`` |
| Variable named ``WIREGUARD_PRESHARED_KEY`` | ``GLUETUN_WIREGUARD_PRESHARED_KEY`` |
| Variable named ``WIREGUARD_ADDRESS`` | ``GLUETUN_WIREGUARD_ADDRESSES`` (**plural!**) |

# v2.0 (The Swan 🦢)

**Seedbox version 2 is here!** 🔥

Since there are some breaking changes and a configuration structure migration, a major version was mandatory.

## What's new?

* **Configuration change to new YAML format**
  * Run ``config-updater.sh`` to migrate your old services.conf to the new config.yaml format.
  * ⚠️ ``jq`` (v1.5+) and ``yq`` (v4+) are now requirements
  * Easier feature switches
  * If a service is missing, it won't be enabled by default like before. The config is now more declarative.
  * Traefik routing rules are now dynamically generated in a file in Traefik config directory, so no more Docker labels. They became hard to maintain due to all possibilities caused by VPN support or custom files for example.
  * New config syntax documented in the [Configuration Guide](doc/configuration.md#configuration-structure-and-parameters).
* **VPN support**
  * With ``gluetun`` service, you can now place any service behind a VPN.
  * Default gluetun configuration is Wireguard "custom" mode, but see below...
  * More details in the [VPN section of the Configuration Guide](doc/configuration.md#vpn).
* **Support custom services and docker-compose yaml files**
  * Place a docker-compose yaml file in ``services/custom/`` directory, add a service in your config.yaml specifying a ``customFile``, and you are set.
  * Support Plex hardware transcoding using a custom-file, already available in the ``services`` directory (just specify a ``customFile`` on plex service - see [config.sample.yaml](config.sample.yaml)).
  * More details in the [Configuration Guide](doc/configuration.md#add-your-own-service).
* **Support arbitrary Traefik rules**
  * Place a Traefik YAML in ``samples/custom-traefik/`` directory, it will be copied in the Traefik configuration folder.
  * Ideal to forward traffic to other services which do not belong to this seedbox.
  * More details in [this section of the Configuration Guide](doc/configuration.md#integration-with-other-services-custom-traefik-config)
* **Disable certificates for some domains**
  * Using the flag ``httpOnly: true`` on a service, access any service in unsecure mode, delegating certificates management on a higher level (reverse proxy, firewall...). More details in the [Configuration Guide](doc/configuration.md#disable-https-completely).
* **Multiple hosts for any services**
  * The new config structure allows for more customization, for example you can now have many routes on the same service. Let's say, a local unsecured route + a secured one for remote access. Or anything you want.
* **More customization**
  * Such as http authentication which is no more hardcoded but configurable for each service.
  * Configurable paths on host for persistent data
* **New services**
  * ``Gluetun``: [VPN client (see above)](https://github.com/qdm12/gluetun)
  * ``Heimdall``: [Dashboard](https://github.com/linuxserver/Heimdall)
  * ``Readarr``: [Ebook and comic monitor](https://github.com/Readarr/Readarr)
  * ``Komga``: [Comic Book Manager](https://github.com/gotson/komga)
  * ``Kavita``: [Comic / Book Manager](https://github.com/Kareadita/Kavita)
  * ``Syncthing``: [P2P files synchronization](https://github.com/linuxserver/docker-syncthing)
* ⚠️ Docker compose v2.2+ is now required

And also:

* ``update-all.sh`` is now called ``run-seedbox.sh`` but its purpose is the same.
* More checks in ``run-seedbox.sh``. For example, throws an error if Flood is enabled but not Deluge, or if VPN is enabled on a service but the VPN client is not.
* You can now specify where your data lives on your host through new environments variables (see [.env.sample](.env.sample)).
  * This change is backward-compatible as the ``run-seedbox.sh`` script will default to the old "/data/torrents" and "/data/config" paths if these variables are not set.
* ``networks:`` section is now aligned with the new docker compose syntax
* ⚠️ Nextcloud-db has moved. It is now in ``/data/config`` (or somewhere else if you set the new variables for host paths) (see below how to mitigate the errors). [See the dedicated section below](#nextcloud-db-has-moved).
* Disable Traefik access logs
* New flag ``--debug`` for ``run-seedbox.sh`` to see what is happening during configuration parsing.
* Releases are named after LOST mythology. I exhausted all the characters of Person of Interest, so that's time for a change. Only geeks will get it, I know.

## How to migrate

```sh
./config-updater.sh
# Check the content of your .env file (in comparison with .env.sample which brings new variables)
# Also, check your generated config.yaml and read the config documentation (in doc/configuration.md)
./run-seedbox.sh
```

When everything runs smoothly, you can delete your old configuration file which is now useless:

```sh
rm -f services.conf
```

## Nextcloud-db has moved

Since commit e4ede925a8ce09b177206f30487a889da9e10334, nextcloud-db directory (mapped on /var/lib/mysql) has moved from
``/data/nextcloud-db`` to ``$HOST_CONFIG_PATH/nextcloud-db`` (*/data/config/nextcloud-db by default*).

To ensure a smooth transition, you will have to move the directory nextcloud-db into the correct new location, then run some commands to fix the schema:

```sh
mv /data/nextcloud-db/ /data/config/
./run-seedbox.sh
source .env
docker exec -it nextcloud-db mysql_upgrade -u root -p${MYSQL_ROOT_PASSWORD}
docker restart nextcloud nextcloud-db
```

Ensure everything runs nicely by looking at nextcloud-db and nextcloud logs, and by accessing your Nextcloud web UI.
